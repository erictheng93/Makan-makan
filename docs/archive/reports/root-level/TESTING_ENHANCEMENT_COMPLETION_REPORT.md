### 3.4 Package.json 腳本增強

#### 新增腳本

```json
{
  "scripts": {
    // 視覺測試腳本
    "storybook": "cd apps/admin-dashboard && pnpm storybook",
    "build-storybook": "cd apps/admin-dashboard && pnpm build-storybook",
    "test:visual": "npx percy exec -- npx playwright test tests/visual/",
    "test:visual:chromatic": "cd apps/admin-dashboard && pnpm chromatic",

    // 安全測試腳本
    "test:security": "bash tests/security/run-zap-scan.sh",
    "test:security:snyk": "snyk test --all-projects --severity-threshold=high",
    "test:security:full": "pnpm run test:security:snyk && pnpm run test:security"
  }
}
```

#### 使用範例

```bash
# 本地視覺測試
pnpm storybook                    # 啟動 Storybook 開發環境
pnpm build-storybook              # 建置靜態 Storybook
pnpm test:visual:chromatic        # 執行 Chromatic 測試
pnpm test:visual                  # 執行 Percy 測試

# 本地安全測試
pnpm test:security:snyk           # 快速 Snyk 掃描 (僅高嚴重性)
pnpm test:security                # OWASP ZAP 完整掃描
pnpm test:security:full           # 執行所有安全測試
```

### 9.2 工作流程整合

```
Pull Request 工作流程

1. 開發者提交 PR
   ↓
2. CI/CD 自動執行所有測試
   ├─ 單元測試
   ├─ E2E 測試
   ├─ 視覺測試 ⭐
   └─ 安全測試 ⭐
   ↓
3. 測試結果通知
   ├─ GitHub Status Checks
   ├─ PR Comment (性能、安全摘要)
   └─ Slack 通知 (失敗時)
   ↓
4. Code Review
   ├─ 開發者審查程式碼
   ├─ 設計師審查視覺變更 (Chromatic/Percy)
   └─ 安全工程師審查安全報告 (Snyk/ZAP)
   ↓
5. 批准與合併
   ├─ 所有測試通過
   ├─ Code Review 批准
   └─ 自動合併 (optional)
   ↓
6. 部署到 Staging
   └─ 僅當所有檢查通過
```
