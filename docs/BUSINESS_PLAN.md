## 1. 執行摘要

### 1.1 公司願景

MakanMakan 致力於成為亞太地區領先的夜市與商圈數位平台，透過邊緣運算與封閉式代幣帳本，把分散的線下小商家聚合成可搜尋、可一次付款的數位市集。

### 1.2 核心價值主張（v2.0）

- **聚合流量**：夜市 / 商圈兩層市集——消費者一次搜尋整區攤商的餐點與服務，解決小攤「沒官網、沒 SEO、靠走動被發現」的流量痛點
- **平台代幣**：封閉式代幣（代幣）＋ 卷，建立跨店通用的預付消費閉環。**平台內消費以內部帳本扣款，不接真正金流、不逐筆串接收單商**——代幣不可兌回現金、不可轉讓、不可換取任何有價證券；法遵完成前僅做小規模封閉 pilot，並保留消保或法定情境下的退費處理（見 §5.5.5、§5.1）
- **商家零負擔**：餐廳管理功能（點餐 / KDS / 列印 / 排班）全部免費，作為加入平台的商家後台——平台靠交易流、封閉式代幣與行銷服務變現，**不向商家收工具月費**（既有訂閱模組降級為功能開關/權限分層基礎設施，非主要收入線，見 §5.1）
- **極致性能 / 低成本營運**：Cloudflare 全球邊緣運算，無伺服器維運成本、PWA 離線可用（P99 < 300ms 為目標/驗證環境值；部分擴展能力為已實作但待 production enablement，見 §4.3 註）

### 1.3 市場機會

> **v2.0**：市場基礎是**平台中介交易額（GMV）**，而非餐廳管理軟體授權市場——舊 v1.0 引用的「全球餐廳管理軟體市場 $78.5 億美元 TAM」已不適用（詳見 §3.1）。

台灣夜市 + 商圈線下小商家年可中介 GMV 約 **NT$1,500 億**（情境估算；分層與保守／基準／樂觀敏感度見 §3.1）。逾 **15 萬家**餐飲與服務小商家普遍缺乏線上曝光、數位會員與點數工具，正是平台聚合的切入點。

### 1.4 融資需求

- **種子輪目標**：NT$50,000,000（≈ US$1.5M）— 覆蓋平台 J 曲線 Y1–Y2 谷底（見 §9.1）
- **資金用途**：團隊 / BD (48%)、市場拓展與首儲補貼 (26%)、法遵與代幣治理 (16%)、預備金 (10%)
- **預期回報**：Year 4 轉正、Year 5 平台營收 ≈ NT$359M，種子輪基準情境 ~11x（見 §9.4）

### 1.5 重大策略修正（v2.0）：兩台引擎與收入重定向

> 本節為 v2.0 新增，記錄商業模式的根本性轉向。**結論：聚焦「夜市/商圈平台」（引擎 B），移除「餐廳 SaaS 訂閱月費」（引擎 A 的變現方式）。**

#### 1.5.1 你手上其實有兩台引擎

從 codebase 的 schema 可讀出兩條互相矛盾的商業路線：

|          | 引擎 A：餐廳 SaaS                                                                  | 引擎 B：夜市 / 商圈 Marketplace                                                         |
| -------- | --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 程式證據 | `subscriptions.ts`（trial/basic/pro/enterprise + 功能模組）、POS、KDS、列印、排班 | `markets`、`discovery`、`credits`（代幣）、`coupons`（卷）、`service_bookings`、平台抽成 |
| 本質     | 賣「工具」給商家                                                                  | 經營「流量 + 封閉式代幣帳本」的平台                                                     |
| 收入     | 月費訂閱                                                                          | 平台抽成 + 儲值沉澱 + 卷                                                                |
| 護城河   | 幾乎沒有（功能可複製）                                                            | 雙邊網路效應（很強，但很難啟動）                                                       |

舊版 BUSINESS_PLAN（v1.0）寫的是引擎 A（餐廳 SaaS、月費 <$10、種子輪），但過去半年實際開發的程式碼（night-market vision、代幣、discovery）是引擎 B。**這個錯位就是商業化三問難以回答的根因。**

#### 1.5.2 商業化三問拆解

**Q1：解決了誰的問題？** 區分「使用者」與「痛到願意付錢的人」：

- 引擎 A 解決餐廳老闆的數位化——但台灣中小餐飲對「管理系統」痛感低、付費意願弱；月費壓到 <$10 不是優勢，是「對方不願付錢」的警訊。紅海絞肉機（iCHEF / 肚肚 / 點點）。
- 引擎 B 解決「消費者找不到、攤商沒流量」——夜市攤商沒官網、沒 SEO、現金為主、靠走動被發現。`discovery` + 跨店搜尋 + 代幣＝把分散小攤聚合成「可搜尋、可一次付款的市集」。這個痛是真的，且 Uber Eats / foodpanda 服務不到夜市這種低客單、高密度、現金攤。
- **PMF 在引擎 B，不在 A。A 是 B 的商家端工具，是手段不是生意。**

**Q2：向誰收費？** → 見 §5.1（四條收入線：儲值沉澱 / 交易抽成 / 卷 / 平台整合）。**移除訂閱月費。**

**Q3：誰「願意」付費（願意 ≠ 受益）？**

| 對象                          | 受益 | 願意付                       | 怎麼收                          |
| ----------------------------- | ---- | ---------------------------- | ------------------------------- |
| **夜市 / 商圈自治會 · 管委會** | ✅   | ✅✅✅ 最被忽略的金主         | 整區導入費 + 抽成分潤（見 §5.6） |
| 消費者                        | ✅   | ✅✅（願儲值、不願付月費）    | 儲值沉澱 + 卷                   |
| 連鎖 / 中型餐廳               | ✅   | ✅✅（願付整合 / 加值）       | 平台整合 add-on                |
| 單一小攤 / 夜市攤商           | ✅   | ❌ 幾乎不付月費               | 免費工具換上架，靠抽成          |
| 地方政府 / 商圈處             | ✅   | ✅ 專案制                     | 數位轉型標案、振興整合          |

**最該敲的門不是一家家餐廳，而是自治會 / 管委會 / 地方政府商圈處**：一個自治會點頭＝一次拿下整區供給端 + 既有人流，把 marketplace 最致命的「雙邊冷啟動」變成一個 B2B2C 銷售問題（落地 SOP 見 §5.6）。

### 2.1 公司簡介

**公司名稱**：MakanMakan（馬來語「吃吃」之意）  
**成立時間**：2025年  
**公司類型**：科技新創公司  
**總部位置**：台灣  
**員工人數**：初創團隊

### 2.2 使命宣言

> 「讓每一個夜市與商圈都有自己的數位市集，讓最小的攤商也能被看見、被搜尋、被回購。」

我們相信科技應該是普惠的。透過 Cloudflare 邊緣運算與封閉式代幣帳本，我們把原本只有大型連鎖才能負擔的數位流量與會員經濟，以零月費、零硬體的方式帶給每一個夜市攤商與商圈小店。

### 2.3 核心競爭優勢

對比「外送平台」「餐廳 POS/SaaS」「夜市現況（純現金）」三類替代方案：

| 優勢領域        | MakanMakan（夜市/商圈平台）        | 外送平台（Uber Eats / foodpanda） | 餐廳 POS/SaaS（iCHEF 等） |
| --------------- | ---------------------------------- | --------------------------------- | -------------------------- |
| 攤商抽成 / 費用 | ~5% 成交抽成、零月費零硬體         | 30–35% 高抽成                     | 月費 + 硬體綁定            |
| 供給聚合        | 自治會一次帶整區（B2B2C）          | 逐家簽約                          | 逐家銷售工具              |
| 支付 / 點數模式 | 跨店通用封閉式代幣 + 卷（不可兌現、不可轉讓） | 第三方收單                        | 不含金流 / 外接收單        |
| 適配場景        | 低客單、高密度、現金攤、夜市/商圈   | 外送、較高客單                    | 有店面的正規餐廳          |
| 消費者黏著      | 儲值預付 + 跨攤 discovery          | 平台補貼依賴                      | 無消費者側                |
| 邊際成本        | 趨近 0（邊緣運算）                 | 高（物流 / 補貼）                 | 中                         |

> 我們不與 iCHEF / Toast 在「餐廳管理工具」象限競爭，也不與外送平台在「高抽成物流」競爭——我們開的是**外送平台覆蓋不到、POS 服務不了的夜市/商圈封閉式代幣與會員市場**。

## 3. 市場分析

### 3.1 目標市場規模（v2.0：從「餐廳軟體市場」改為「夜市/商圈 GMV 市場」）

> **v2.0 重新定義**：我們的營收基礎是**平台中介的交易額（GMV）**——抽成 + 儲值沉澱 + 破值，而**不是**賣餐廳管理軟體的授權數。因此市場規模應以「夜市/商圈線下小商家的可中介 GMV」衡量，而非「餐廳管理軟體市場」（舊 v1.0 的 $78.5 億美元 TAM 已不適用）。
>
> ⚠️ 以下數字為**情境估算**（🅐 為核心假設），匯率以 1 USD ≈ 32 TWD 換算。

#### TAM（Total Addressable Market）— 台灣夜市 + 商圈線下小商家年交易 GMV

| 參數                              | 估值 🅐                          |
| --------------------------------- | ------------------------------- |
| 全台夜市數                        | ~300 個                         |
| 平均可上架攤數 / 夜市             | ~80 攤                          |
| 每攤年營業額                      | ~NT$300 萬（NT$1 萬/晚 × 300 晚） |
| → 夜市 GMV 池                     | ~NT$720 億 / 年                 |
| ＋ 商圈 / 街邊小商家（餐飲＋服務） | ~NT$780 億 / 年                 |
| **TAM（可中介 GMV）**             | **≈ NT$1,500 億 / 年（≈ US$4.7B）** |
| 平台 take rate（抽成＋破值 blended） | ~8.5%                           |
| **→ 可貨幣化 TAM（平台營收潛力）** | **≈ NT$128 億 / 年（≈ US$400M）** |

#### SAM（Serviceable Addressable Market）— 可服務、可數位化的夜市/商圈

聚焦台灣、有自治會 / 管委會可對接、且屬觀光型或都會型（具人流與儲值意願）的夜市/商圈：

- 可服務比例（佔 TAM GMV）：~40% 🅐
- **SAM GMV ≈ NT$600 億 / 年（≈ US$1.9B）**
- **→ 可貨幣化 SAM（平台營收潛力）≈ NT$51 億 / 年（≈ US$159M）**

#### SOM（Serviceable Obtainable Market）— 5 年實際拿下

以「逐個夜市/商圈導入」推進（單一夜市 unit economics 見 §5.5、展店曲線與財務見 §9.2）：

|                          | Y1  | Y2  | Y3  | Y4   | Y5   |
| ------------------------ | --- | --- | --- | ---- | ---- |
| 累計上線夜市/商圈        | 3   | 12  | 35  | 80   | 160  |
| 平台 GMV（NT$億 / 年）   | 0.4 | 2.6 | 8.1 | 19.8 | 41.4 |
| 平台營收（NT$M / 年）    | 3.5 | 22  | 70  | 172  | 359  |

- **Y5 SOM ≈ NT$41 億 GMV / 年**，約佔 SAM 的 **~7%**、TAM 的 **~3%**——留有極大成長餘裕。
- 海外（馬來西亞 MYR、越南 VND，`credits.currency` 已支援多幣別）為 SAM 之外的後續擴張，本計劃未計入。

#### 資料來源與敏感度（誠實聲明）

> 上述標 🅐 的數字目前為**內部情境假設，尚待外部來源佐證**，對外版本應補來源並以首座燈塔夜市實測校準。

- **待補來源**：夜市數 / 攤數（主計總處、交通部觀光署夜市調查）、每攤年營業額（產業報告或燈塔夜市實測）、blended take rate、breakage 率、CAC、自治會轉換率。**目前 8% breakage、NT$150K CAC、160 區展店均為假設，無第三方來源或實測背書。**
- **三情境敏感度（關鍵變數）**：

  | 變數 | 保守 | 基準 🅐 | 樂觀 |
  | --- | --- | --- | --- |
  | 每攤年營業額 | NT$200 萬 | NT$300 萬 | NT$400 萬 |
  | blended take rate | 6% | 8.5% | 10% |
  | Y5 上線夜市/商圈 | 100 | 160 | 220 |
  | **→ Y5 平台營收（粗估）** | **≈ NT$160M** | **≈ NT$359M** | **≈ NT$580M** |

  （粗估係以基準情境線性縮放，非重算模型；正式對外需以 §9.2 驅動因子重建三情境損益。）
- **募資前置條件（go/no-go gate）**：A 輪 / 規模化前，**首座燈塔夜市需完成 90 天試營運**並達標：上架攤數、儲值滲透率、月 GMV、破值率、消費者與攤商留存。未達標前不規模化獲區、不規模化收受儲值（另見 §5.5.5 法遵前提）。

### 3.2 目標客群分析（三方）

平台連結三方，**付費決策方 ≠ 主要受益方**（見 §1.5 Q3）：

#### 付費決策方 — 自治會 / 管委會 / 地方政府（B2B2C 入口）

- 對象：夜市自治會、商圈管委會、地方政府商圈處
- 在意：招商 / 數位化 KPI、商圈人流與營收數據、商圈補助核銷、組織營運經費
- 為何是首要敲門對象：單點決策帶整區供給，解雙邊冷啟動（見 §5.6）

#### 供給端 — 夜市攤商 / 商圈小商家 / 服務業者

- 對象：夜市攤位、街邊小吃、外帶店、餐車，以及可預約的服務業者（`service_bookings`）
- 痛點：沒官網、沒 SEO、現金為主、靠走動被發現、被外送平台 30–35% 抽成壓垮
- 我們給：零月費零硬體的免費後台 + ~5% 低抽成 + 整區流量；攤商**不是付費方，是供給方**

#### 需求端 — 消費者

- 對象：逛夜市 / 商圈的在地與觀光客
- 痛點：找不到想吃的、每攤分開付款麻煩、現金不便
- 我們給：跨攤搜尋（discovery）、一次付款、儲值代幣 + 卷回饋；**願儲值、不願付月費**——儲值沉澱與破值即平台主收入

### 3.3 競爭分析

#### 替代方案比較

| 替代方案                              | 服務對象       | 抽成 / 費用              | 對夜市/商圈的覆蓋                 |
| ------------------------------------- | -------------- | ----------------------- | -------------------------------- |
| **外送平台**（Uber Eats / foodpanda） | 有外送需求商家 | 30–35% 抽成             | 不適低客單現金攤、攤商抗拒高抽成 |
| **餐廳 POS / SaaS**（iCHEF 等）       | 有店面餐廳     | 月費 + 硬體             | 不服務無固定店面的攤位           |
| **儲值 / 支付**（街口 / 一卡通）      | 一般零售       | 交易手續費              | 有金流，無「商圈聚合 + 點餐/預約」 |
| **夜市現況**（純現金）                | —              | —                       | 無數位、無數據、無線上流量       |
| **MakanMakan**                        | 夜市/商圈三方  | ~5% 抽成 + 儲值浮存/破值 | 專為夜市/商圈設計，B2B2C 整區導入 |

#### MakanMakan 差異化定位

```
              高抽成 / 高費用
                     │
      外送平台 ●     │
                     │     ● 餐廳 POS/SaaS
   ──────────────────┼──────────────────
                     │
   純現金（無數位）● │  ● MakanMakan
                    │   (低抽成 + 封閉式代幣 + 整區聚合)
              低抽成 / 低費用

   單店 / 單點 ◄─────┼─────► 整區 / 平台聚合
```

> 定位空白點：**低抽成、封閉式代幣帳本、且專做「整區夜市/商圈聚合」**——這個象限目前沒有玩家。

## 4. 產品與服務

### 4.1 產品架構

MakanMakan 提供完整的餐廳管理生態系統，包含三大前端應用與強大的後端服務：

```
┌─────────────────────────────────────────────────────────────┐
│                    MakanMakan 產品生態系統                    │
├─────────────────┬─────────────────┬─────────────────────────┤
```

## 5. 商業模式

### 5.1 收入模式（v2.0：移除訂閱月費，改走平台交易 / 代幣帳本）

> **v2.0 重大修正**：本平台**不再以「向餐廳收 SaaS 訂閱月費」作為收入引擎**。理由見 §1.5——台灣中小餐飲對「管理工具」付費意願極弱，月費 <$10 是紅海訊號而非優勢。餐廳管理功能（POS / KDS / 列印 / 排班 / 菜單）**全部免費**，定位為「加入平台就送的商家後台」，用來換取供給端上架與代幣帳本綁定，而非直接變現。

MakanMakan 採用 **平台型（Marketplace）收入模式**，依商業健康度排序四條收入線：

#### 5.1.1 四條收入線（依健康度排序）

| #    | 收入線                          | 機制                                                       | 對應 schema                                     | 付費者                       | 健康度 |
| ---- | ------------------------------- | ---------------------------------------------------------- | ----------------------------------------------- | ---------------------------- | ------ |
| 🥇 1 | **儲值沉澱（Float / Breakage）** | 消費者儲值代幣，沉澱餘額＝浮存現金，未用完部分（破值）＝收入 | `credit_accounts.balanceCents`、`expiresAtMs`、`entryType=expire` | 消費者                       | ★★★★★  |
| 🥈 2 | **交易抽成（Commission）**       | 跨店點餐 / 預約服務每筆抽成                                 | `markets.platformFeeRateBps`、`service_bookings` | 商家（從營收拆，非額外掏錢） | ★★★★   |
| 🥉 3 | **卷 / 行銷服務（Vouchers）**    | 商家出資促銷，平台收服務費或價差                           | `coupons`、`user_coupons`                        | 商家行銷預算                 | ★★★★   |
| 4    | **平台整合 / 加值（Add-on）**    | Uber Eats / foodpanda 串接、進階分析等，對中大型商家計次或專案收費 | `platform_integrations`、`ai-analytics`         | 連鎖 / 中型商家             | ★★★    |

**關鍵轉變**：收費對象從「商家的 IT 預算」（不願付）轉向「**消費者的預付消費/代幣使用**」與「**商家的行銷預算**」（願付，且付費意願高一個量級）。

#### 5.1.2 為什麼移除訂閱月費

- **付費意願**：管理工具對攤商＝成本；行銷與流量對攤商＝投資。後者才掏得出錢。
- **護城河**：訂閱模式功能可複製、無網路效應；封閉式代幣帳本＋雙邊聚合有網路效應與轉換成本。
- **冷啟動**：月費要求每家店各自決策（慢）；平台模式可透過自治會一次帶進整區供給（見 §5.6）。
- **單位經濟**：浮存與抽成隨 GMV 與儲值規模放大，邊際成本趨近於零（見 §5.5）。

> 訂閱模組（`subscriptions.ts` 的 trial/basic/pro/enterprise）**保留為「功能開關 / 權限分層」基礎設施**，用於控制 add-on（收入線 4）的存取，**不再作為月費獲利引擎**。

### 5.3 獲區策略（B2B2C，以「區」為單位）

逐家攤商銷售無效（攤商不付月費、決策分散）；改以「自治會 → 整區」為獲取單位（落地 SOP 見 §5.6）。

#### 5.3.1 獲區成本（CAC，以夜市/商圈為單位）

| 管道                  | 目標 CAC / 區        | 說明                                |
| --------------------- | -------------------- | ----------------------------------- |
| 自治會 / 管委會直銷   | NT$120,000           | 主力：一次帶進整區供給              |
| 地方政府商圈處 / 標案 | NT$80,000            | 數位轉型補助核銷，CAC 可被補助攤平   |
| 燈塔案例口碑 / 推薦   | NT$50,000            | 已上線商圈推薦鄰近商圈              |
| **加權平均**          | **~NT$150,000 / 區** | 一次帶進 ~40 攤 → 每攤 ~NT$3,750     |

#### 5.3.2 單區終身價值（LTV）

```
單區 LTV 計算（成熟期）：
- 單區年貢獻毛利：~NT$2.8M
- 預估區留存壽命：5 年以上（自治會綁定 + 儲值轉換成本）
- 保守取 3 年

LTV = NT$2.8M × 3 ≈ NT$8.4M

LTV / CAC = NT$8.4M / NT$150K ≈ 56x ✅
(健康比率 > 3x；CAC 一次帶整區，攤平到每攤極低)
```

> 與 v1.0「逐家餐廳 LTV/CAC」最大差異：**獲取單位是「區」不是「店」**——一次決策帶進整區供給與既有人流，把雙邊冷啟動一次性解決。

### 5.4 定價策略

平台不向商家收月費，定價即「**take rate（抽成）＋ 儲值機制 ＋ 卷服務費**」的組合：

**① 交易抽成（`platformFeeRateBps`，可分區設定）**

- 基準 ~5%（500 bps），遠低於外送平台 30–35%，對攤商極具吸引力
- 高人流觀光商圈可上調；冷啟動期可下調或前 N 月免抽以拉高上架率

**② 儲值機制（消費者端）**

- 不直接對消費者收費；收入來自**浮存週轉 + 破值**（§5.5）
- 以首儲贈卷、儲值回饋拉高儲值率與黏著

**③ 卷 / 行銷服務（商家端，自願）**

- 商家出資促銷，平台收服務費或價差——是「商家願付的行銷預算」，非「不願付的工具費」

**④ 自治會分潤**

- 抽成中撥固定比例回饋自治會，綁定長期協作（§5.6.3）

**定價哲學**：對攤商「成交才收費、且遠低於外送平台」；對消費者「不收費、代幣使用還有回饋」；把變現壓在**消費者預付消費/代幣使用**與**商家行銷預算**，而非商家的 IT 預算。

### 5.5 浮存 / Breakage 財務模型（單一夜市 Unit Economics）

> **交付物 A**。以 `credits` 帳本結構（`credit_accounts.balanceCents` / `reservedCents` / `expiresAtMs`、`credit_ledger_entries.entryType ∈ {topup, spend, refund, expire}`）為基礎，由下而上推導單一夜市的代幣使用規模 → breakage / 抽成 → 單位經濟。
>
> ⚠️ 所有數字皆為**情境假設（台灣夜市場景）**，非實測；標示 🅐 為核心假設，落地後須以真實 ledger 校準。

#### 5.5.1 帳本 → 財務指標對應

| 財務概念                   | 帳本來源                                                   | 定義                             |
| -------------------------- | ---------------------------------------------------------- | -------------------------------- |
| 月代幣發行 (Topups)        | `Σ amountCents WHERE entryType='topup'`（月）              | pilot 代幣發行量；法遵前不等同正式金流收入 |
| 月消費 (Spend, ≈GMV-via代幣) | `Σ ABS(amountCents) WHERE entryType='spend'`（月）         | 代幣實際被花掉                   |
| 代幣未使用餘額             | `Σ balanceCents`（全體 active 帳戶當下）                   | 尚未消費的代幣負債；法遵前不得作為可自由運用現金 |
| 破值 (Breakage)            | `Σ ABS(amountCents) WHERE entryType='expire'` + 永不動用餘額 | 到期 / 永不消費 → 認列為收入      |

#### 5.5.2 核心假設（🅐）

| 參數                          | 值              | 說明                              |
| ----------------------------- | --------------- | --------------------------------- |
| 上線攤數 / 夜市               | 40              | 與 night-market vision 範例一致   |
| 營業夜數 / 月                 | 24              |                                   |
| 每攤每晚「平台」GMV           | NT$3,000 🅐      | 僅計走平台的交易，非攤商總營收     |
| → 月平台 GMV / 夜市           | **NT$2.88M**    | 40 × 24 × 3,000                   |
| 代幣支付滲透率                | 40% 🅐           | 其餘為現金 / 卷 / 到店付           |
| → 月代幣消費 (Spend)          | **NT$1.15M**    | GMV × 40%                         |
| 代幣消費週轉天數 (D)          | 21 天 🅐         | 預付/點數常見 2–4 週              |
| 破值率 (b)                    | 8% 🅐            | 業界 5–15%，取中保守              |
| 平台抽成 (platformFeeRateBps) | 500 bps = 5% 🅐  | `markets.platformFeeRateBps` 可調 |
| 代幣未用餘額可運用收益        | 0% 🅐            | pilot 階段不把未用代幣當可運用現金 |

#### 5.5.3 單一夜市・成熟期月收入

```
月平台 GMV ........................ NT$2,880,000
├─ 月代幣消費 (Spend) ............. NT$1,152,000   (×40%)
├─ 月代幣發行 (Topups) ............ NT$1,252,000   (Spend / (1−b)，穩態)
│
代幣未使用餘額（負債） ............ NT$  806,000   (Spend × D/30)
─────────────────────────────────────────────────
收入線 1 ｜ Breakage ............. NT$  100,000   (Topups × 8%)
收入線 2 ｜ 交易抽成 5% .......... NT$  144,000   (GMV × 5%)
收入線 1b｜ 未用餘額收益 ......... NT$        0   (pilot 階段不認列)
─────────────────────────────────────────────────
單一夜市・成熟期月收入 ≈ NT$ 245,000   （年化 ≈ NT$2.94M）
```

> **CTO 誠實註記**：pilot 階段不要把未用代幣當生息資產或自由現金流賣給投資人。代幣不可兌現、不可轉讓、不可換取有價證券，但只要存在「預付後跨店消費」特徵，仍需先完成儲值/禮券/消保定性；法遵前 breakage 也只能作情境估算，不能當正式收入承諾。

#### 5.5.4 Ramp（滲透率爬升）與單位經濟

實際非一上線就成熟，代幣滲透率需時間爬升：

| 階段   | 月數  | 代幣滲透率 🅐 | 月收入（抽成 + 破值） |
| ------ | ----- | ------------ | --------------------- |
| 導入期 | M1–M2 | 10%          | ~NT$61K               |
| 成長期 | M3–M6 | 25%          | ~NT$153K              |
| 成熟期 | M7+   | 40%          | ~NT$245K              |

**拿下一個夜市的單位經濟：**

| 項目                                              | 估值 🅐       |
| ------------------------------------------------- | ------------ |
| CAC（一次性：自治會 BD + 攤商說明會 + 初期客戶成功） | NT$150,000   |
| 平台邊際成本 / 月（Cloudflare + 對帳 + 客服分攤）   | NT$10,000    |
| 成熟期月貢獻（收入 − 邊際成本）                    | ~NT$235,000  |
| **回收期（自成熟期起）**                          | **< 1 個月** |
| 含 ramp 的實際回本                                | 約 4–6 個月  |
| 首年單一夜市淨貢獻                                | ~NT$1.8M     |

> 一個自治會 = 一次帶 40 攤 = CAC 攤平到每攤約 NT$3,750，遠低於逐家銷售餐廳 SaaS 的 CAC。**B2B2C 整區獲客是把 CAC 一次性化、把供給端冷啟動一次性解決的關鍵。**

#### 5.5.5 法遵前提（必讀，先於放大）

儲值代幣涉及預付 / 儲值 / 商品服務兌換。即使代幣**不可兌回現金、不可轉讓、不可換取任何有價證券**，只要可由消費者預先取得、日後向指定商圈或多個攤商換取商品/服務，仍可能被檢視為商品服務禮券、單用途/多用途儲值，或在規模化時觸及《電子支付機構管理條例》相關要求。因此 pilot 階段採以下硬限制：

1. 不接真正金流；代幣僅作封閉式 pilot 點數，不對外承諾可兌現或轉讓。
2. 設定單人、單區、單月代幣上限；僅限指定商圈/活動內消費。
3. 不允許代幣換回現金、任何形式的有價證券、第三方可轉讓權利或法幣清分。
4. 保留消保或法定情境下的退費/更正流程，避免把「不可兌現」誤寫成「任何情境永不退款」。
5. 規模放大前完成法律意見書，確認禮券/儲值/電支定性、履約保障、到期與 breakage 認列。

> 本模型即 §9.2 五年損益的單區驅動因子；§9 已以「夜市數 × 單一夜市 unit economics」全面重建（v2.0）。

### 5.6 B2B2C 落地：拿下一個自治會（Pitch + SOP）

> **交付物 B**。對應現有 `markets` / `restaurant_market_memberships` / `market_join_requests`、onboarding 地理 auto-assignment、`credits`、`coupons`、`discovery` 流程。

#### 5.6.1 為什麼是自治會（而非逐家攤商）

Marketplace 最致命的是雙邊冷啟動：沒攤商→消費者不來；沒消費者→攤商不上架。**自治會 / 商圈管委會是「單點決策、整區供給」的鑰匙**：一次點頭帶進整區攤商 + 既有人流，把冷啟動從「N 家店各自決策」變成「1 個組織決策」。

#### 5.6.2 給自治會的 Pitch（價值主張）

| 自治會在意                       | 我們給                              | 對應能力                          |
| -------------------------------- | ----------------------------------- | --------------------------------- |
| 招商 / 數位化 KPI、商圈補助核銷   | 整區數位點餐 + 線上市集，作為數位轉型成果 | `markets` + `discovery`           |

| 商圈人流 / 營收看不見            | 整區人流、熱銷、營收 dashboard      | 平台數據彙整                      |
| 想要回流客、會員經濟            | 區域通用儲值代幣 → 客人預付綁定整區回流 | `credits`（跨店通用）             |
| 組織自身的營運經費              | **抽成分潤回饋自治會**（平台抽成撥一部分） | `markets.platformFeeRateBps` 可設定 |

**一句話 pitch**：「我們免費幫您整個商圈上線數位市集與會員儲值，攤商不用付錢、不用買機器；平台只在成交時抽一點，並把其中一部分回饋給自治會作為營運基金。」

#### 5.6.3 收費 / 分潤模式（對自治會）

- **抽成分潤（recurring）**：平台抽成（`platformFeeRateBps`）中撥固定比例回饋自治會，綁定其長期協作誘因。

### 6.1 品牌定位

**品牌口號**：「逛夜市更好逛，開商圈更好賺」

### 6.2 行銷管道策略

#### 6.2.1 供給端 BD（50% 預算）— 拿下自治會與整區

| 管道                  | 作法                          | 預期效益            |
| --------------------- | ----------------------------- | ------------------- |
| 自治會 / 管委會直銷   | 一對一拜訪、MOU、攤商說明會    | 一次帶進整區供給    |
| 地方政府商圈處 / 標案 | 數位轉型補助、振興整合案       | 補助攤平 CAC、官方背書 |
| 攤商開戶地推          | 說明會現場掃碼上線、收銀協助    | 拉高單區上架率      |

#### 6.2.2 消費者啟動與口碑（35% 預算）— 啟動儲值飛輪

| 管道              | 作法                            | 目的                  |
| ----------------- | ------------------------------- | --------------------- |
| 開幕首儲活動      | 首儲贈卷、儲值回饋（`coupons`） | 拉動第一筆儲值、衝滲透率 |
| 燈塔商圈 PR / 社群 | 樣板案例、在地 KOL、打卡活動    | 帶人流、複製到鄰區    |
| 跨攤 discovery 體驗 | 線上市集搜尋、一次付款          | 提升回購與客單        |

#### 6.2.3 數位行銷（15% 預算）— 輔助

- **SEO 關鍵字**：夜市線上點餐、商圈會員儲值、夜市數位化、各夜市美食地圖（在地長尾）
- **付費廣告**：地理圍欄鎖定各夜市/商圈周邊客群（非鎖定餐廳老闆）
- **內容**：各夜市美食地圖、攤商故事、儲值優惠——對消費者，不對 IT 買家

### 6.3 獲取策略（B2B2C 雙漏斗）

#### 6.3.1 供給端「獲區漏斗」（B2B）

```
                ┌─────────────────┐
                │  自治會接觸     │  接觸 N 個自治會/商圈
                └────────┬────────┘
                         │ 簽 MOU
                ┌────────▼────────┐
                │  攤商說明會     │  整區攤商招募
                └────────┬────────┘
                         │ ≥75% 攤商上線
                ┌────────▼────────┐
                │  整區上線       │  discovery 開站
                └────────┬────────┘
                         │ 開幕首儲
                ┌────────▼────────┐
                │  儲值飛輪啟動   │  進入 B2C 漏斗
                └─────────────────┘
```

#### 6.3.2 需求端「儲值飛輪」（B2C）

```
   首儲贈卷 → 消費者儲值 → 跨攤消費(discovery) → 浮存/破值
        ▲                                          │
        └──────── 儲值回饋 / 卷 拉動回購 ◄──────────┘
```

> 兩個漏斗串接：B2B 把整區供給與人流一次帶進來，B2C 把人流轉成代幣使用與回購。**沒有「免費試用 → 付費升級」的 SaaS 漏斗——攤商一開始就免費，變現在消費者預付消費/代幣使用與商家行銷。**

### 6.4 留存策略（三方）

**攤商留存**：

- 整區流量與線上訂單帶來實質增收
- 低抽成 vs 外送平台的長期成本優勢
- 月報：攤位熱銷 / 營收 / 客群數據

**消費者留存**：

- 儲值餘額與卷形成自然回購誘因
- 跨攤 discovery 與會員回饋
- 區域通用代幣，逛哪攤都能用

**自治會續約**：

- 商圈人流 / 營收 dashboard 作為招商與補助核銷成果
- 抽成分潤作為組織營運經費
- 推薦鄰近商圈（口碑複製）

**目標指標**：

- 攤商月留存 > 90%
- 消費者 90 天儲值回購率 > 40%
- 自治會續約率 > 90%

## 7. 營運計劃

### 7.1 組織架構

> **v2.0 全面重建**：本章從「SaaS 訂閱 ARR 模型」改為「夜市展店 → GMV → 浮存/抽成/破值」模型，與 §3.1（市場規模）、§5.1（收入線）、§5.5（單一夜市 unit economics）一致。幣別以 **NTD 為主、US$ 對照**（1 USD ≈ 32 TWD）。所有數字為情境估算（🅐 為核心假設）。

## 10. 風險分析

> **v2.0 重排**：平台模式的風險與 SaaS 不同——最大風險不是「客戶流失」，而是**電支法遵、雙邊冷啟動、破值/儲值假設失真、自治會關係集中**。

### 10.1 風險矩陣

```
影響程度
    高 │  ③ 雙邊冷啟動   ① 電支/儲值法遵
       │
    中 │  ⑤ 技術依賴     ② 破值/儲值假設失真
       │                ④ 自治會關係集中
    低 │  ⑥ 競爭/外送平台
       └──────────────────────────────
              低          中          高
                      發生機率
```

### 10.2 主要風險與對策

#### 風險 1：電支 / 儲值法遵（最高優先）

**風險等級**：高  
**描述**：封閉式代幣即使不可兌現、不可轉讓、不可換取有價證券，仍可能因預付後跨店兌換商品/服務而落入商品服務禮券、單用途/多用途儲值或電子支付相關分析；若達一定規模，可能涉及儲值上限、履約保障、備付金信託、是否需電支執照或與持牌機構合作。

**對策**：

- 規模放大前完成法遵盤點（商品服務禮券、單/多用途儲值、跨店通用認定、儲值上限）
- pilot 階段採小額、封閉、不可兌現、不可轉讓、不可換取有價證券的代幣政策
- 履約保障 / 備付金信託 / 與持牌機構合作列為規模化選項
- 未用代幣餘額不作可自由運用現金或生息資產認列
- 破值認列方式與會計 / 稅務事前確認

#### 風險 2：破值 / 儲值假設失真

**風險等級**：中高  
**描述**：代幣支付滲透率、破值率（8% 🅐）、儲值週轉天數若顯著低於假設，將直接打擊兩條主收入線。

**對策**：

- 以真實 `credit_ledger_entries` 持續校準模型（entryType 分布、過期金額）
- 滲透率不足時以首儲贈卷 / 回饋加碼，並下調該區抽成換交易量
- 收入結構保留抽成（不依賴破值）作為安全墊

#### 風險 3：雙邊冷啟動失敗

**風險等級**：中高  
**描述**：攤商上架但消費者不儲值 / 不點，或反之；單區未達臨界規模即停滯。

**對策**：

- B2B2C：以自治會一次帶進整區供給（§5.6），先解供給端
- 燈塔商圈打樣，集中資源做出一個跑通的樣板再複製
- 開幕首儲活動 + discovery 跨攤搜尋拉動消費者側網路效應

#### 風險 4：自治會關係集中

**風險等級**：中  
**描述**：單一區營收綁定單一自治會 / 管委會，關係生變或改朝換代恐影響整區。

**對策**：

- 分潤機制綁定長期誘因（§5.6.3）；合約期與續約條款
- 攤商與消費者的儲值黏著形成「即使換約也難遷移」的轉換成本
- 分散布局多區，降低單一關係集中度

#### 風險 5：技術平台依賴

**風險等級**：中  
**描述**：過度依賴 Cloudflare 平台。

**對策**：

- 架構保持可移植性、監控定價變動、準備備援（AWS / GCP）
- 與 Cloudflare 建立合作關係

#### 風險 6：競爭 / 外送平台下沉

**風險等級**：低  
**描述**：Uber Eats / foodpanda 或本地玩家切入夜市/商圈。

**對策**：

- 抽成 ~5% vs 外送 30–35% 的結構性價差是天然護城河
- 儲值代幣 + 自治會關係 + 跨攤 discovery 形成網路效應與轉換成本
- 服務外送平台覆蓋不到的低客單、高密度、現金攤場景

### 10.3 風險緩解預算

| 風險類別          | 年度預算 (NT$) | 用途                              |
