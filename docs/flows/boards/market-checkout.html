市集跨攤結帳

一次付款、每攤各自成單。沒有跨攤交易可用，所以靠的是補償而不是回滾。

全景板：master user flow
流程文件：04-customer-group-and-market.md
對照原始碼：2026-08-21

建立 → 套卷 → 付款 → 回調

1

送出跨攤購物車

同一攤不能在購物車出現兩次。逐攤檢查：市集啟用、攤位是會員、攤位允許訪客單。

POST /api/v1/market-checkouts400 vendor 重複
2

逐攤建立 child order

每一攤都是一筆獨立的訪客訂單，各自發一把 guest token（4h）與活躍鎖（2h）。

market_checkout_child_orders一個裝置身分覆蓋整筆結帳
3

中途失敗 → 補償

第 3 攤失敗時，回滾前兩攤已建立的訂單並清鎖，再把失敗記錄下來。重試安全：每次都是新的 checkoutId。

compensateFailedMarketCheckout補償失敗 → 人工處理佇列
4

寫入 session

KV（4 小時）＋ D1 各一份。KV 那份是顧客端追蹤用，D1 那份是後台查詢與對帳用。

status = submittedpayment_status = pending
5

套用卷（可選）

只吃平台級券（coupons.restaurant_id IS NULL）。折扣按攤位金額等比分攤，讓各攤送給金流商的金額加總仍等於總收費。

POST /market-checkouts/:id/voucherMARKET_CHECKOUT_ALREADY_PAIDVOUCHER_ALREADY_APPLIED · VOUCHER_EXPIRED
6

付款

已付款則直接回傳既有結果，不再送金流。付款前先 reserveUsage 保留卷額度，失敗即 releaseReservation。

POST /market-checkouts/:id/payIdempotency-Key → 供應商
7

供應商回調

先驗簽再認列。卷的 coupon_usage 是在驗證過的付款成功之後才寫，且每個 checkout 只加一次 used_count。

POST /market-checkouts/payment-webhooks/:providerMARKET_CHECKOUT_WEBHOOK_SIGNATURE_INVALID
8

顧客追蹤

逐攤狀態。弄丟 guest token 可用手機末幾碼換回。

GET /market-checkouts/:idPOST /market-checkouts/:id/guest-token

兩種分帳模式

splitMode怎麼切什麼時候用能不能對帳
child_transactions 平台逐攤各開一筆交易 預設 不能——provider 對帳端點只支援下一列
provider_split 交給金流商做分潤 環境變數指定，或用代幣付款時強制 可以：POST /market-checkouts/admin/:id/reconcile

三個結構性取捨

沒有跨攤交易，只有補償

  • 每攤是獨立訂單，而 D1 也沒有互動式交易。
  • 所以建立階段失敗時是「把已建立的回滾掉」，不是「整批不提交」。
  • 補償本身失敗會被記錄成待人工處理的失敗 session。

真相分散在 KV 與 D1

  • 付款與退款都是先讀 KV、讀不到再讀 D1。
  • KV 的 4 小時 TTL 過了之後，顧客端追蹤頁會退化。

卷的核銷點在最後

  • 套用時只是記在 session 上，不佔額度。
  • 付款時 reserveUsage 保留，失敗歸還。
  • coupon_usage 只在驗證過的付款成功後才寫，重放不會重複核銷。
