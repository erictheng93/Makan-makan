### 2.2 具體案例分析

#### 案例 1: restaurant_id 不一致

```sql
-- 0001_initial_schema.sql (2025-10-11)
CREATE TABLE restaurants (
    id INTEGER PRIMARY KEY AUTOINCREMENT,  -- ❌ INTEGER
    ...
);

-- 0010_ai_analytics_system.sql (2025-10-06)
CREATE TABLE ai_configurations (
    id TEXT PRIMARY KEY,                    -- ⚠️ TEXT
    restaurant_id TEXT NOT NULL,            -- ❌ TEXT 但引用 INTEGER
    FOREIGN KEY (restaurant_id) REFERENCES restaurants(id)  -- 類型不匹配!
);

-- 0035_leave_management_system.sql (2025-10-26)
CREATE TABLE leave_types (
    restaurant_id INTEGER NOT NULL,         -- ❌ 又變回 INTEGER
    ...
);
```

**問題影響**:

- ❌ 外鍵約束無法正確執行
- ❌ JOIN 查詢可能失敗
- ❌ 資料完整性無法保證

#### 案例 2: 時間戳格式混亂

```sql
-- 方式 1: DATETIME
CREATE TABLE ai_configurations (
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 方式 2: INTEGER (Unix秒)
CREATE TABLE leave_types (
    created_at INTEGER NOT NULL DEFAULT (strftime('%s', 'now'))
);

-- 方式 3: INTEGER (Unix毫秒)
CREATE TABLE restaurants (
    created_at INTEGER NOT NULL  -- 註釋說是毫秒
);
```

**問題影響**:

- ❌ 時間計算複雜
- ❌ 排序和比較困難
- ❌ 前端需要多種解析邏輯

#### 案例 3: Migration 混亂

```
Password 相關 Migrations 的演變:

002_password_security_migration.sql     ← 改用 bcrypt
0029_fix_password_hash.sql.temp_skip   ← 修復 hash
0030_add_is_active.sql.temp_skip       ← 加欄位
0031_update_passwords.sql.temp_skip    ← 更新密碼
0032_fix_admin_password.sql.temp_skip  ← 修復管理員

❌ 問題:
   - 5 個 migration 做同一件事
   - 4 個被禁用,不確定最終狀態
   - 無法重新執行 migrations
```

);

    latitude REAL,
    longitude REAL,

    CHECK (longitude BETWEEN -180 AND 180)
    -- ✅ 數值範圍驗證
